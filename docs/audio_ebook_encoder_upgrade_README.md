# 音频、电子书与编码器升级方案

本文档用于记录 InsScreen 墨水屏项目后续升级方案，方便分阶段实现、测试和追溯。

- 文档创建日期：2026-07-27
- 项目路径：`D:\insScreen_project\InsScreen_project`
- 主控：ESP32-S3
- Flash：16 MB
- PSRAM：8 MB Octal PSRAM，80 MHz
- 当前 Git 基线：`dd4a123`

> 注意：本文记录的是实施方案，不代表所有功能已经完成。每完成一个阶段，应更新文末的实施记录。

## 1. 目标功能

计划移除现有无源蜂鸣器，并增加以下功能：

1. I2S 喇叭功放和音乐播放。
2. TXT 电子书阅读。
3. 后续增加简化版 EPUB 阅读。
4. 使用一个带按压开关的旋转编码器替代三个独立按键。
5. 保留网页配置、网页上传和网页 OTA 升级能力。
6. 音乐、书籍、字体和封面统一存放在 SD 卡。

第一阶段不支持 PDF。扫描版 PDF 对解码内存、程序空间和墨水屏刷新速度都不合适。

## 2. 当前资源基线

截至本文创建时：

| 资源 | 当前情况 |
| --- | --- |
| 当前固件大小 | 3,024,096 字节 |
| 当前单个程序分区 | 3 MB，即 3,145,728 字节 |
| 当前程序分区剩余 | 121,632 字节，约 4% |
| 运行时内部 RAM 空闲 | 曾观察到约 82-85 KB |
| HTTPS 期间最大内部连续块 | 曾下降到约 26 KB |
| 运行时 PSRAM 空闲 | 曾观察到约 6.8 MB |

结论：

- 8 MB PSRAM 足够实现音乐、TXT 和简化 EPUB。
- 当前 3 MB 程序分区不够继续扩展，必须先调整分区。
- 删除蜂鸣器只能释放少量程序空间，不能解决分区不足。
- 音频 DMA 必须占用内部 RAM，不能全部放入 PSRAM。

## 3. 功能资源估算

以下是用于规划的估算值，最终以编译结果和实机日志为准：

| 功能 | 预计程序增量 | 预计 PSRAM/缓冲占用 |
| --- | ---: | ---: |
| 编码器驱动 | 小于 10 KB | 可忽略 |
| I2S、WAV、MP3 | 100-250 KB | 150-500 KB |
| TXT 阅读器 | 50-150 KB | 100-500 KB |
| 简化 EPUB | 200-600 KB | 500 KB-2 MB |
| TTF 字形缓存 | 取决于字体库 | 建议预留约 500 KB |

目标是所有新功能完成后仍保留：

- 至少 200 KB 程序分区余量。
- 至少 50 KB 内部 RAM 空闲。
- 至少 20 KB 内部 RAM 最大连续块。
- 至少 3 MB PSRAM 空闲。

## 4. 推荐 Flash 分区

保留 factory、ota_0 和 ota_1 三个程序槽，每个扩大到 4 MB。这样既能继续网页 OTA，也保留 factory 恢复能力。

建议的新 `partitions.csv`：

```csv
# Name,     Type, SubType,  Offset,    Size,      Flags
nvs,        data, nvs,      0x9000,    0xC000,
otadata,    data, ota,      0x15000,   0x2000,
phy_init,   data, phy,      0x17000,   0x1000,
factory,    app,  factory,  0x20000,   0x400000,
ota_0,      app,  ota_0,    0x420000,  0x400000,
ota_1,      app,  ota_1,    0x820000,  0x400000,
coredump,   data, coredump, 0xC20000,  0x20000,
fontfs,     data, spiffs,   0xC40000,  0x2E0000,
spiffs,     data, spiffs,   0xF20000,  0xE0000,
```

调整后的结果：

- 每个程序槽为 4 MB。
- 以当前固件计算，程序空间约剩 1.17 MB。
- `fontfs` 保持 2.875 MB。
- 用户 SPIFFS 缩小为 896 KB。
- 图片、音乐、书籍和通用字体必须迁移到 SD 卡。

### 分区迁移注意事项

修改分区表后需要进行一次完整分区迁移，不能只上传普通 app bin。

迁移前必须：

1. 把 SPIFFS 图库复制到 SD 卡。
2. 备份 Wi-Fi、天气、新闻、显示、传感器等配置。
3. 记录当前面板型号和显示方向。
4. 确认 SD 卡上的备份文件可以读取。
5. 不擦除 SD 卡。

迁移完成后，后续普通固件仍然可以通过网页只上传 bin 文件进行 OTA。

## 5. SD 卡目录规划

建议在现有 `/sdcard/epd` 下增加：

```text
/sdcard/epd/music       音乐文件
/sdcard/epd/books       TXT 和 EPUB 文件
/sdcard/epd/bookmarks   阅读进度和书签
/sdcard/epd/fonts       电子书使用的 TTF/OTF 字体
/sdcard/epd/covers      书籍封面缓存
/sdcard/epd/cache       分页索引等可重建缓存
```

存储原则：

- SPIFFS 只保留系统缓存和少量关键文件。
- 用户媒体全部放 SD 卡。
- 配置继续保存在 NVS，同时支持备份到 SD 卡。
- 可重建的索引和封面缓存不得写入 NVS。

## 6. 音频硬件方案

第一版建议使用单声道 I2S Class-D 功放 `MAX98357A`，它不需要额外音频 DAC，软件和硬件都比较简单。

建议配置：

- 功放：MAX98357A。
- 喇叭：4 欧姆、3 W。
- 音频格式：先支持 WAV，再支持 MP3。
- 功放必须有硬件关断或使能控制。
- 停止播放和休眠时关闭功放并卸载 I2S，降低静态功耗。

暂定引脚候选：

| 信号 | GPIO | 状态 |
| --- | ---: | --- |
| I2S BCLK | GPIO11 | 待原理图最终确认 |
| I2S LRCLK/WS | GPIO12 | 待原理图最终确认 |
| I2S DATA OUT | GPIO13 | 待原理图最终确认 |
| 功放使能 | GPIO17 | 删除蜂鸣器后可复用 |

GPIO11、GPIO12、GPIO13 目前只作为候选，改板前必须核对完整原理图、模组引脚限制和 PCB 走线。

### 功放供电注意事项

1. 功放附近放置 470-1000 uF 电解电容和 100 nF 陶瓷电容。
2. 5 V 供电和电池升压电路要能承受音乐峰值电流。
3. 功放电源和数字电源走线要避免互相干扰。
4. MAX98357A 是桥接输出，喇叭两端都不能接 GND。
5. 音量上限应由软件限制，避免供电压降引发棕断复位。

## 7. 编码器硬件与操作方案

旋转编码器具有 A、B 和按压开关三个信号，可以复用原三个按键引脚：

| 编码器信号 | GPIO | 说明 |
| --- | ---: | --- |
| A 相 | GPIO9 | 可作为旋转输入和唤醒源候选 |
| B 相 | GPIO8 或 GPIO14 | 候选普通输入脚，最终按原理图确认 |
| 按压开关 | GPIO3 | 可作为确认和唤醒按键 |

硬件建议：

- A、B、按压信号分别增加 10K 上拉。
- 根据实测增加小电容或使用纯软件消抖。
- GPIO46 是输入/启动绑带相关引脚，不建议连接编码器 A/B 相。编码器相位
  在某些停留位置会持续拉低，可能影响复位时的绑带电平。
- GPIO8、GPIO14 当前只是在代码层面没有发现占用，改板前仍需核对原理图。
- 休眠时优先使用编码器按压唤醒，旋转不要求唤醒设备。

统一操作定义：

| 操作 | 默认功能 |
| --- | --- |
| 顺时针旋转 | 下一项、下一页或增加音量 |
| 逆时针旋转 | 上一项、上一页或降低音量 |
| 单击 | 确认、播放或暂停 |
| 长按 | 返回上一级 |
| 首页长按 | 进入休眠 |

软件层不能让各页面直接读取 GPIO。编码器驱动应统一生成“左转、右转、单击、长按”事件，再交给当前页面处理。

## 8. 音频软件架构

建议拆分为以下模块：

```text
encoder.c/.h         编码器采样、消抖和事件
audio_i2s.c/.h       I2S 和功放使能
audio_player.c/.h    播放、暂停、停止、音量和播放列表
audio_decoder_wav.c  WAV 解码
audio_decoder_mp3.c  MP3 解码
media_library.c/.h   扫描 SD 卡媒体文件
```

内存规则：

- MP3 输入环形缓冲放 PSRAM，建议 64-128 KB。
- PCM 解码缓冲放 PSRAM，建议 32-128 KB。
- I2S DMA 缓冲放内部 RAM，第一版建议控制在 8-16 KB以内。
- 解码任务栈需要记录高水位，不能凭感觉设置。
- 所有大块内存申请都要检查失败并安全停止播放。

并发规则：

- 播放音乐时延后新闻和天气 HTTPS 自动更新。
- 播放音乐时禁止同时进行大型图片转换。
- 页面切换可以继续播放音乐，但 SD 卡访问需要统一管理。
- 墨水屏刷新前后检查内部 RAM，避免 DMA 申请失败。
- 休眠、OTA 和关机前必须停止解码、关闭 I2S 和功放。

第一版音频功能范围：

- WAV PCM 播放。
- MP3 播放。
- 播放、暂停、上一首、下一首。
- 音量调节和音量上限。
- 顺序、单曲和随机播放。
- SD 卡拔出时安全停止，不复位。

暂不支持 AAC、FLAC、蓝牙音频和网络流媒体。

## 9. 电子书软件架构

建议拆分为：

```text
ebook_library.c/.h   扫描书籍和读取元数据
ebook_reader.c/.h    打开、翻页、跳转和书签
ebook_txt.c/.h       UTF-8 TXT 解析
ebook_epub.c/.h      后续的简化 EPUB 解析
glyph_cache.c/.h     字形缓存
```

### 第一阶段：TXT

- 只保证 UTF-8 和带 UTF-8 BOM 的 TXT。
- 支持自动分页、上一页、下一页和跳页。
- 保存每本书的阅读位置。
- 页面索引保存在 SD 卡，损坏后可以重新生成。
- 翻页时不把整本书读入内存，只按偏移流式读取。

### 字体方案

现有 `fontfs` 字体是按受控字符集生成的，不能覆盖任意中文电子书。

电子书需要：

1. 把完整中文 TTF/OTF 字体放到 `/sdcard/epd/fonts`。
2. 按需栅格化当前页面使用的汉字。
3. 把常用字形缓存在 PSRAM。
4. 字形缓存满后按最近最少使用规则释放。

### 第二阶段：简化 EPUB

只支持 EPUB 中适合墨水屏的基础内容：

- 章节列表。
- 普通段落和标题。
- 基础加粗、换行和分页。
- 简单插图和封面。

不保证复杂 CSS、脚本、动画、数学公式和固定版式。PDF 不纳入第一版计划。

## 10. 网页与程序空间优化

当前 `web` 目录文件总量约 652 KB，并作为资源嵌入程序。增加音频和电子书之前应完成：

1. 抽取各网页重复的 CSS 和 JavaScript。
2. 对网页资源进行 gzip 压缩后嵌入。
3. 删除不再使用的蜂鸣器网页和接口代码。
4. 音乐和电子书网页只提供管理功能，不嵌入大型图片或字体。
5. 每次编译记录 app bin 大小，低于 200 KB余量时停止继续堆功能。

## 12. 验收标准

### 编码器

- 快速和慢速旋转都不丢步、不乱跳。
- 单击和长按不会互相误触发。
- 可以从休眠状态通过按压唤醒。

### 音频

- 连续播放 MP3 两小时不复位、不爆音。
- 播放中翻电子书页面不导致音频中断。
- 停止播放后功放进入低功耗状态。
- SD 卡被拔出时安全停止并显示错误。
- 最大音量时不发生棕断复位。

### 电子书

- 10 MB TXT 不整本载入内存。
- 连续翻页 500 次不复位、不持续丢失内存。
- 重新上电恢复到上次阅读位置。
- 中文缺字时显示替代符号，不崩溃。

### OTA 和系统

- 新分区下网页 OTA 能在 ota_0 和 ota_1 之间正常切换。
- OTA 失败时仍能启动旧固件。
- 音乐播放期间发起 OTA 时先安全停止音频。
- 新闻、天气、画廊和现有显示功能不能因新增模块退化。

### GPIO 选型约束

- 不使用 GPIO26-GPIO32，它们和模组 Flash/PSRAM 配置有关。
- GPIO0、GPIO3、GPIO45、GPIO46 属于启动绑带相关引脚，不能随意增加会改变上电电平的外设。
- GPIO19、GPIO20 如果要保留原生 USB，则不分配给功放或编码器。
- GPIO43、GPIO44 如果要保留串口日志，则不优先使用。
- 编码器 A/B 相可能在静止时保持高或低，因此必须避开关键启动绑带脚。
- 所有候选引脚必须在新原理图完成后再冻结，不能只根据“代码没有使用”判断可用。

推荐的第一版候选分配是：

```text
编码器 A       GPIO9
编码器 B       GPIO8（备选 GPIO14）
编码器按压      GPIO3
I2S BCLK       GPIO11
I2S WS         GPIO12
I2S DATA OUT   GPIO13
功放 EN/SD     GPIO17
```

## 14. 总体软件结构

新增功能不能直接塞进现有页面回调。建议增加三个独立层：

```text
输入层
  encoder_driver -> input_event_queue

业务层
  ui_controller
    -> audio_player
    -> ebook_reader
    -> 原有 display_mode

资源层
  storage_manager -> SD 卡
  font_manager    -> TTF 字体与字形缓存
  audio_i2s       -> I2S 功放
  display_policy  -> 墨水屏显示所有权
```

基本原则：

1. 编码器驱动只产生事件，不知道当前显示的是音乐还是电子书。
2. 页面控制器根据当前模式解释事件。
3. 音频播放器不直接刷新墨水屏，只上报状态变化。
4. 电子书渲染必须通过现有显示策略申请显示权。
5. 所有 SD 卡路径和文件访问由统一存储模块管理。
6. 新闻、天气、图库和电子书不能各自无保护地同时访问大块内存或 SD 卡。

### 建议增加的显示模式

```c
DISPLAY_MODE_MUSIC   /* 音乐列表和正在播放页面 */
DISPLAY_MODE_READER  /* 电子书阅读页面 */
```

进入阅读器后可以保存上次模式；进入音乐页面不等于自动播放。设备复位后可以恢复阅读位置，但不能自动让功放出声。

## 15. 编码器事件设计

建议统一事件定义：

```c
typedef enum {
    INPUT_EVENT_ROTATE_CCW,   /* 逆时针一格 */
    INPUT_EVENT_ROTATE_CW,    /* 顺时针一格 */
    INPUT_EVENT_CLICK,        /* 短按后松开 */
    INPUT_EVENT_LONG_PRESS,   /* 持续按住达到长按时间 */
    INPUT_EVENT_RELEASE,      /* 长按后的松开，需要时使用 */
} input_event_type_t;

typedef struct {
    input_event_type_t type;
    int16_t steps;            /* 快速旋转时允许一次携带多格 */
    uint32_t timestamp_ms;    /* 事件产生时间，用于过滤重复事件 */
} input_event_t;
```

建议时间参数：

- A/B 相稳定消抖：2-5 ms，根据实测波形调整。
- 按键消抖：20-40 ms。
- 短按：按下时间小于 600 ms。
- 长按：持续 800 ms 后只触发一次。
- 长按触发后松开不能再补发一次短按。

旋转解码应使用完整 Gray Code 状态表。不要只在 A 相边沿读取 B 相，否则机械抖动时容易反向跳动或一次跳多格。

### 不同页面的事件映射

| 当前页面 | 旋转 | 单击 | 长按 |
| --- | --- | --- | --- |
| 首页 | 切换功能 | 进入功能 | 休眠 |
| 音乐列表 | 选择歌曲 | 播放所选歌曲 | 返回首页 |
| 正在播放 | 调音量 | 播放/暂停 | 返回音乐列表 |
| 电子书列表 | 选择书籍 | 打开书籍 | 返回首页 |
| 阅读页面 | 翻页 | 打开阅读菜单 | 返回书籍列表 |
| 阅读菜单 | 选择项目 | 确认 | 关闭菜单 |

## 16. 音频播放器状态机

播放器只能处于以下一个状态：

```text
STOPPED -> OPENING -> PLAYING <-> PAUSED
                     |   |
                     v   v
                   STOPPING -> STOPPED

任意状态发生 SD/解码/I2S 错误 -> ERROR -> STOPPED
```

各状态要求：

- `STOPPED`：I2S 已卸载，功放使能为关闭，文件已关闭。
- `OPENING`：验证文件、读取头信息、申请缓冲，不允许功放提前开启。
- `PLAYING`：解码任务持续填充 PCM，I2S 消费数据。
- `PAUSED`：停止送入新数据，功放可延时关闭，文件位置保留。
- `STOPPING`：停止任务、清空 DMA、关闭文件，最后关闭功放。
- `ERROR`：记录错误原因并完成和 `STOPPING` 相同的资源释放。

推荐的启动顺序：

1. 检查 SD 卡仍然挂载。
2. 打开音频文件并验证格式。
3. 申请 PSRAM 环形缓冲和解码器内存。
4. 创建 I2S 通道和内部 DMA 缓冲。
5. 先输出一小段零采样。
6. 打开功放使能，减少“啪”的冲击声。
7. 开始正常解码和播放。

推荐的停止顺序必须反过来：先停止生产 PCM，再等待或清空 DMA，然后关闭功放、删除 I2S、释放内存、关闭文件。

### 第一版音频参数

- 输出：单声道或把立体声混合成单声道。
- 采样位宽：16 bit。
- 常见采样率：44.1 kHz 和 48 kHz。
- MP3 码率目标：32-320 kbps。
- 音量：内部保存 0-100，但采用非线性映射，低音量更容易细调。
- 默认最大音量先限制为 70%，完成供电压降测试后再决定是否开放。

### 建议任务和缓冲预算

| 项目 | 位置 | 初始预算 |
| --- | --- | ---: |
| 音频控制任务栈 | 内部 RAM | 6-8 KB |
| MP3 输入环形缓冲 | PSRAM | 64-128 KB |
| MP3 解码工作区 | 优先 PSRAM | 50-150 KB |
| PCM 大缓冲 | PSRAM | 32-64 KB |
| PCM 内部中转块 | 内部 RAM | 2-4 KB |
| I2S DMA | 内部 DMA RAM | 8-16 KB |
| 播放列表 | PSRAM | 16-64 KB |

不要在播放循环中反复 `malloc/free`。所有稳定缓冲应在 `OPENING` 一次申请，在 `STOPPING` 一次释放，避免内部 RAM 碎片化。

## 17. SD 卡并发与文件名规则

当前工程使用 SDMMC 1-bit 模式，顺序读取 MP3 的带宽足够。真正需要防范的是多个任务同时访问 FATFS。

当前配置中 `CONFIG_FATFS_FS_LOCK=0`，而音乐、电子书、图库和日志都可能访问 SD 卡。实施时必须选择下面一种方式：

1. 推荐：增加 `storage_manager` 和全局互斥锁，所有操作分成短小读写块。
2. 或者调整 FATFS 文件锁配置，并且仍在应用层规定清晰的文件所有权。

禁止音频任务从开始播放到结束一直占有全局 SD 锁，否则电子书无法翻页。建议音频每次读取 4-16 KB，读完立即释放锁。

### 中文文件名问题

当前 FATFS API 编码是 ANSI/OEM，代码页是 437。直接使用中文文件名存在兼容风险。

第一版最稳妥的做法：

- SD 卡实际文件名使用 ASCII，例如 `book_0001.txt`、`track_0001.mp3`。
- 中文书名和歌曲名保存在 UTF-8 元数据中。
- 网页显示中文标题，但底层打开的是 ASCII 路径。

后续如果要直接支持中文路径，需要切换 FATFS UTF-8 API 编码，并重新测试长文件名、上传、删除、重命名和断电恢复。

### 建议媒体索引格式

`/sdcard/epd/music/library.json` 示例：

```json
{
  "version": 1,
  "tracks": [
    {
      "id": "track_0001",
      "path": "track_0001.mp3",
      "title": "歌曲名称",
      "artist": "歌手",
      "duration_ms": 215000
    }
  ]
}
```

索引只是缓存，删除后应能重新扫描生成。程序不能因为索引损坏就拒绝读取 SD 卡。

## 18. 电子书分页与书签细节

电子书不能整本读入内存。TXT 阅读器应以“文件字节偏移”作为页码索引：

```text
第 0 页 -> 文件偏移 0
第 1 页 -> 文件偏移 1372
第 2 页 -> 文件偏移 2801
...
```

分页过程：

1. 从当前页偏移读取一个小块，例如 8-32 KB。
2. 按 UTF-8 字符边界解码，不能从汉字中间断开。
3. 根据当前屏幕尺寸、字体大小、行距和边距计算换行。
4. 记录下一页起始字节偏移。
5. 只渲染当前页，下一页可以在空闲时预计算。

分页索引建议使用 `uint32_t`。即使一本书有 10,000 页，索引也只约 40 KB，可以放 PSRAM并同步到 SD 卡。

### 分页缓存失效条件

分页索引文件要记录：

- 原书文件大小。
- 原书最后修改时间或内容校验值。
- 屏幕宽高和旋转方向。
- 字体文件标识。
- 字号、行距和页边距。
- 分页算法版本。

任意一项变化都要丢弃旧分页索引重新生成，否则会跳到错误位置。

### 阅读进度保存

建议每本书使用独立记录：

```json
{
  "version": 1,
  "book_id": "book_0001",
  "byte_offset": 2801,
  "page_index": 2,
  "updated_at": 1785081600
}
```

不要每翻一页都写 NVS，这会增加 Flash 擦写。建议：

- 翻页过程中只更新 RAM。
- 每 20 页或每 30 秒异步保存一次到 SD 卡。
- 退出阅读器、休眠、OTA 前立即保存。
- 写入 `.tmp` 文件，关闭并确认成功后再重命名替换正式文件。

NVS 只保存“上次打开的书籍 ID”和少量全局阅读设置，详细进度保存在 SD 卡。

## 19. 字体与 EPUB 实现边界

完整中文 TTF 字体通常有数 MB到十几 MB，不能嵌入 app，也不应全部加载到 PSRAM。

字形缓存的键至少包含：

```text
字体 ID + Unicode 码点 + 字号 + 粗体状态
```

缓存条目保存栅格化后的单色位图和字形尺寸。建议初始缓存上限 512 KB，满后淘汰最久未使用的字形。

简化 EPUB 的读取流程建议为：

1. 读取 ZIP 中央目录，不整本解压。
2. 找到 `META-INF/container.xml`。
3. 找到 OPF 文件并读取 spine 章节顺序。
4. 按章节读取 XHTML。
5. 只解析标题、段落、换行、简单强调和图片。
6. 去除脚本、复杂 CSS 和未知标签。
7. 当前章节按需分页，离开章节后释放临时 DOM。

如果轻量 EPUB 实现后 app 剩余空间低于 200 KB，应停止增加格式功能，不继续加入 PDF。

## 20. 后台任务协调策略

需要增加一个系统资源状态，例如：

```c
typedef struct {
    bool audio_playing;
    bool display_rendering;
    bool image_converting;
    bool ota_running;
    bool sd_available;
} system_activity_t;
```

建议规则：

- `audio_playing=true` 时，新闻和天气到期后只标记“待刷新”，不立即建立 HTTPS。
- 音频暂停或停止后，再执行积压的一次新闻和天气刷新，不重复执行多次。
- `ota_running=true` 时，立即停止音频并禁止启动新的显示转换。
- `image_converting=true` 时，不允许启动 MP3 解码器的大块内存初始化。
- 墨水屏刷新可以和音频播放并行，但不能阻塞高优先级音频填充任务。
- SD 卡卸载前必须通知音频和阅读器关闭文件。

建议音频任务运行在 Core 1，Wi-Fi 默认在 Core 0；但是否固定核心必须以压力测试为准，不能未经测试就到处固定任务。

## 21. 功耗与休眠策略

删除蜂鸣器本身不会显著改变功耗，功放才是新增功耗的主要来源。

功放至少有四种电源状态：

| 状态 | I2S | 功放使能 | 用途 |
| --- | --- | --- | --- |
| 关闭 | 未安装 | 低 | 默认、阅读、待机 |
| 准备 | 已安装 | 低 | 防止启动冲击声 |
| 播放 | 工作 | 高 | 正常输出 |
| 暂停 | 保留或卸载 | 延时后低 | 短暂停或长暂停 |

建议暂停超过 3-5 秒后关闭功放；再次播放时按正常启动顺序恢复。

进入深度睡眠前必须完成：

1. 停止播放任务。
2. 保存音乐位置和阅读进度。
3. 关闭功放使能。
4. 删除 I2S 通道。
5. 刷新并关闭仍打开的 SD 文件。
6. 只保留编码器按压作为主要唤醒操作。

硬件验收时要测量：关机电流、阅读待机电流、暂停电流、正常音量电流和最大音量峰值电流。

## 22. 异常处理与用户可见结果

所有错误都要“退出当前动作并保持系统可用”，不能使用 `ESP_ERROR_CHECK` 处理可预期的媒体错误。

| 异常 | 正确处理 |
| --- | --- |
| SD 卡未插入 | 音乐/书籍页面显示未检测到卡，不复位 |
| 播放中拔卡 | 立即静音、停止任务、关闭功放并记录错误 |
| MP3 文件损坏 | 跳过损坏帧；连续失败后停止该歌曲 |
| 不支持的采样率 | 显示格式不支持，不启动功放 |
| PSRAM 申请失败 | 释放已申请资源，返回列表页面 |
| I2S DMA 申请失败 | 不开启功放，记录内部 RAM 指标 |
| TXT UTF-8 损坏 | 使用替代字符并继续，不能越界读取 |
| 字体缺字 | 显示方框或问号，不崩溃 |
| EPUB 结构损坏 | 关闭书籍并保留其他书籍可用 |
| OTA 启动 | 先安全停止音频和保存阅读进度 |

每种错误至少记录：错误码、文件 ID、内部 RAM空闲、最大连续块、PSRAM空闲、任务栈最低余量和设备运行时间。

## 25. 回滚和恢复方案

分区迁移前保存：

- 旧 `partition-table.bin`。
- 旧 factory/app 固件。
- fontfs 镜像。
- SPIFFS 文件级备份。
- NVS 配置导出。
- 一份注明各烧录偏移的版本清单。

迁移到新分区后，旧的 3 MB app 通常仍能放入新的 4 MB槽，但旧固件是否理解新的 SPIFFS位置必须单独确认。不能只刷旧 app 就假定所有数据分区也恢复。

如果需要完整退回旧分区，必须恢复旧分区表、匹配的 app/fontfs/SPIFFS，并验证 NVS 兼容性。

## 26. 设计决策记录

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 主控 | 继续使用 ESP32-S3 | 8 MB PSRAM足够，无需换主控 |
| 程序槽 | factory + 双 OTA，各 4 MB | 保留网页 OTA 和恢复能力 |
| 用户媒体 | SD 卡 | Flash 容量和擦写寿命不适合音乐/书籍 |
| 功放 | MAX98357A 类 I2S 功放 | 不需要独立 DAC，驱动简单 |
| 第一版音频 | WAV + MP3 | 覆盖常用需求且资源可控 |
| 第一版电子书 | UTF-8 TXT | 最容易保证稳定和分页一致性 |
| 后续电子书 | 简化 EPUB | 只实现墨水屏实际需要的子集 |
| PDF | 暂不支持 | 程序、内存和刷新成本过高 |
| 输入方式 | 旋转编码器 + 按压 | 三根输入线完成导航和确认 |
| GPIO46 | 不作为编码器相位首选 | 编码器静态电平可能影响启动绑带 |
| 中文路径 | 第一版底层使用 ASCII ID | 当前 FATFS 编码配置不适合直接依赖中文路径 |

### 原理图检查表

- [ ] 功放上电默认处于关闭状态。
- [ ] 功放使能脚电平与GPIO17兼容。
- [ ] 功放电源回流不经过电池ADC敏感地线。
- [ ] 喇叭输出没有任何一端接GND。
- [ ] 编码器A/B没有接启动绑带脚。
- [ ] 编码器按压不会在正常上电时持续改变绑带电平。
- [ ] I2S走线远离墨水屏高压升压部分和天线区域。
- [ ] 5 V或3.3 V电源的峰值电流和温升有余量。

## 30. 建议 C 模块接口

以下接口用于限定模块职责，正式实现时可以按现有工程风格微调，但不能让网页、编码器和播放器互相直接操作底层硬件。

### 编码器

```c
/* 初始化GPIO、消抖任务和输入事件队列。 */
esp_err_t encoder_init(void);

/* 在指定时间内等待一个输入事件；超时返回ESP_ERR_TIMEOUT。 */
esp_err_t encoder_wait_event(input_event_t *event, uint32_t timeout_ms);

/* 休眠前停止采样并配置按压唤醒。 */
esp_err_t encoder_prepare_sleep(void);
```

### 音频底层

```c
typedef struct {
    uint32_t sample_rate_hz;  /* 例如44100或48000。 */
    uint8_t channels;         /* 输入可为1或2，实际功放输出为单声道。 */
    uint8_t bits_per_sample;  /* 第一版固定16 bit。 */
} audio_format_t;

/* 创建I2S DMA，但此时功放仍保持关闭。 */
esp_err_t audio_i2s_open(const audio_format_t *format);

/* 写入PCM；必须有超时，不能永久阻塞播放器任务。 */
esp_err_t audio_i2s_write(const int16_t *pcm, size_t frames,
                          uint32_t timeout_ms);

/* 先静音并关闭功放，再删除I2S通道。 */
void audio_i2s_close(void);
```

## 31. 网页端规划

建议只增加一个 `media.html`，通过页签切换“音乐、电子书、设置”三个视图，不为每个功能创建大量独立页面。

### 当前路由容量风险

当前 `http_app.c` 中约有94条路由，`max_uri_handlers` 设置为96。新功能实现前必须处理路由容量，不能直接继续逐条注册接口。

推荐方案：

1. 开启HTTP URI通配匹配。
2. 使用 `/api/media/*` 的统一GET处理器和统一POST处理器。
3. 或使用 `/media_api?op=...`，同一个GET/POST路由根据 `op` 分发。
4. 将 `max_uri_handlers` 调整到112前先测量HTTP服务器启动后的内部RAM变化。
5. 注册失败必须让启动日志明确显示失败的URI，不能静默忽略。

### 建议统一 API

| 请求 | 操作 | 说明 |
| --- | --- | --- |
| `GET /media_api?op=status` | 获取媒体状态 | 返回SD、音乐、阅读和内存状态 |
| `GET /media_api?op=tracks` | 获取音乐列表 | 支持分页，不能一次返回无限列表 |
| `GET /media_api?op=books` | 获取书籍列表 | 返回ID、标题、进度和封面状态 |
| `POST /media_api?op=play` | 播放歌曲 | JSON中传递 `track_id` |
| `POST /media_api?op=pause` | 暂停 | 幂等操作，已暂停仍返回成功 |
| `POST /media_api?op=stop` | 停止 | 必须关闭功放和文件 |
| `POST /media_api?op=volume` | 设置音量 | 取值0-100并受最大音量限制 |
| `POST /media_api?op=open_book` | 打开书籍 | 传递 `book_id` |
| `POST /media_api?op=page` | 翻页或跳页 | 传递方向或页码 |
| `POST /media_api?op=rescan` | 重建媒体索引 | 后台执行，接口不能阻塞很久 |

所有修改状态、上传和删除请求必须经过现有鉴权。API Key、Wi-Fi密码和本地文件绝对路径不能返回给未鉴权页面。

### 上传规则

- 上传数据按4-16 KB分块直接写入SD卡，禁止整文件 `malloc`。
- 先写 `.uploading` 临时文件，完成大小和格式检查后再重命名。
- 连接中断时删除临时文件。
- 文件大小上限应在配置里明确，例如音乐100 MB、电子书50 MB。
- SD剩余空间必须大于文件大小加安全余量。
- 上传过程中不自动开始播放或打开书籍。

### 页面状态

网页必须完整处理：加载中、空列表、SD未插入、正在扫描、上传进度、播放错误、格式不支持和设备忙。轮询状态建议2-5秒一次，页面隐藏时停止高频轮询。

## 32. NVS 配置与版本兼容

蜂鸣器的 `buzzer` 命名空间删除后可以暂时保留旧键，不需要为了清理几个键擦除整个NVS。音频必须使用新的命名空间，不能复用蜂鸣器键名。

建议NVS字段：

```text
namespace: audio
  schema       u8    配置结构版本
  volume       u8    音量0-100
  max_volume   u8    最大允许音量
  play_mode    u8    顺序/单曲/随机
  last_track   str   上次歌曲ID，可选

namespace: reader
  schema       u8    配置结构版本
  font_px      u16   字号
  line_px      u16   行高
  margin_px    u16   页边距
  last_book    str   上次书籍ID
```

高频变化的播放毫秒位置和每页阅读位置不写NVS。它们应按前文策略写入SD卡，避免Flash磨损。

读取配置时：

1. 缺少字段使用安全默认值。
2. `schema`低于当前版本时执行迁移。
3. `schema`高于当前版本时不能按旧结构强行解析。
4. 所有数值再次限制范围，不能信任NVS里一定是合法值。
5. SD配置备份/恢复功能要同步支持 `audio` 和 `reader` 命名空间。

## 34. 开发完成定义

不能以“能够播放一次”或“能够打开一本书”作为完成。一个阶段只有同时满足以下条件才算完成：

1. 功能代码和网页入口都可用。
2. 正常流程和错误流程都有实机测试。
3. 连续压力测试没有复位和持续内存下降。
4. 断电、拔卡、OTA和休眠时资源可以安全释放。
5. bin大小、内部RAM、PSRAM和任务栈余量都有记录。
6. 配置升级和旧配置兼容已经验证。
7. 文档、实施记录和Git提交保持一致。
